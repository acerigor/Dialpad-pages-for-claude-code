CoreConnect Design Guidelines

The visual system behind the CoreConnect application — colors, typography, and component patterns across the leads table, filter panel, dialer, buckets, modals, contact panel, notifications, layout settings, conference call experience, the full mobile / responsive shell (drawer, mobile search, pinned-name table, FAB, focus-mode call, drill-down filters), the shared Communication History pattern (split layout, scope toggle, audio player, transcript, notes, SMS / Email / New Message composers) used by Call / Message / Voicemail history, and the Table ⇄ Kanban view switcher with its drag-drop board. Use this as the single reference when building new screens so they stay consistent with the existing product.

Extracted from coreconnect_leads_v79.html + coreconnect_voicemail_history_v5.html + coreconnect_message_history_v38.html · Dark theme · DM Sans + DM Mono

Responsive breakpoints

Max‑widthLabelWhat it triggers
1080pxDialer overlay Dialer panel switches from desktop "push" (docked third column) to tablet "overlay" — slides in from the right over content with a backdrop. Used by Call/Message/Voicemail history pages.

820pxMaster-detail drill-down On pages with a split layout (Call/Message/Voicemail history), the list pane goes full-width and the detail pane becomes an overlay that slides in from the right when a row is selected. A back arrow in the detail header returns to the list.
640pxPhone shell The full mobile shell engages: 64px sidebar hidden, hamburger button shown, mobile drawer enabled, search collapses to a magnifier toggle that opens the full-screen MSO overlay, FAB appears, modals + slide-in panels become full-screen takeovers, and form inputs go to 16px font to suppress iOS zoom.
540pxTight phone A handful of narrow-phone tweaks on the Voicemail page (and similar dense screens) — used sparingly when the 640px layout still feels cramped on smaller devices. Reach for it only when a real overflow problem exists at 640.

How to choose a breakpoint. Don't invent new ones. Pick the smallest one in the table whose behavior already matches what your screen needs — the responsive system is meant to read consistently from screen to screen. If you find yourself wanting "just one more breakpoint", check whether the issue can be solved by adjusting layout inside an existing tier (flex-wrap, min-width, etc.) before adding a new media query.

An unread item carries two signals: the name flips to --tx at font-weight:600, and a .vm-dot (7px accent-blue circle, 7px right margin) sits to its left. Already-read rows keep the muted name color and drop the dot. The contrast between the two states should be obvious at a glance — that's the entire point of the treatment.

It appears in the voicemail detail header next to the phone number when the current user is the one who left the voicemail. Same tint as bdg-new — both signal "this is yours" or "this is fresh".

AI Compose button (contact panel)

A small accent-blue square button (.cp-ai-btn) sits next to the SMS/Email message composer inside the contact panel. Clicking it inserts an AI-suggested draft into the composer field. The visual is a tinted blue tile with a small sparkle/star glyph; it lives only in the contact panel, not in the top header.

SVG portrait avatars

For the conference call's video tiles we don't have real photos, so each participant gets a generated SVG portrait — a two-stop linear gradient (light-to-dark of their accent color) with a subtle radial highlight overlaid, and the initials at 140px in #fff. The gradient angle is derived from a hash of the participant's name, so no two adjacent tiles look identical. The portrait fills the tile via preserveAspectRatio="xMidYMid slice".

Toggles & selection controls

05
Layout Surfaces

Beyond the leads table, CoreConnect has several larger surfaces — the persistent app shell (sidebar + top header), modals, slide-in panels, grouped buckets, a messaging view, a notifications panel, and the full conference-call experience. They reuse the same tokens but introduce a few patterns of their own, documented here.

App shell — sidebar

64px-wide vertical rail · fixed left · z 70 · sits below the top header
CRM Customer
DP
Main content area — leads table, contact panel, etc.

The sidebar is a thin vertical rail (64px wide, position:fixed, top:64px so it begins below the header, height:calc(100vh - 64px), z:70). Background is --bg with a thin right border in --brd. Inside, navigation items are 40×40 with 10px radius. Default color is --mu; hover lifts to --tx on a 5%-white wash; the active item flips to a solid --ac background with white icon (CRM Customer in the demo). A flex spacer pushes Settings + the account avatar to the bottom, separated by a 32px hairline divider. Each item has a data-label attribute that drives a tooltip on hover — a pill anchored to the right of the icon, in --sur2 background with an accent border and accent-blue text. The account avatar at the very bottom (currently "DP" on a green tile) opens the account menu.

App shell — top header

Full-width strip · 64px tall · fixed top · z 60 · logo left, bell right
CC
CoreConnect
Bell — three states (default, unread, call-active)

The top header is intentionally sparse — only the logo (32×32 rounded-square brand mark + "CoreConnect" wordmark) on the left, and the notifications bell on the right. Specs: position:fixed, height:64px, full width, z:60, background --bg with a thin bottom border in --brd. The bell is a 40×40 square in --mu; hover wash is 5% white; clicking toggles the notifications panel and flips the bell to an accent-blue tinted "active" state. Two dots can stack on the bell: the red dot appears when there are unread notifications, the green dot (with a 1.5s pulse) appears whenever a conference call is active — both are 8px circles with a 2px --bg border so they read cleanly. The bell also has its own tooltip below it (vs. to the right like the sidebar items) using the same accent-bordered pill style.

Touch & Tap (Mobile)

When CoreConnect runs on a phone or tablet, every interactive element competes with the user's fingertip. Fingertips are roughly 10–14 mm wide (about 45–60 CSS pixels) and lack the precision of a mouse pointer. Anything smaller than ~44 px becomes a hit-or-miss target — frustrating for everyone, but especially for users with larger hands, motor difficulties, or those using the app on the move. These rules define what "fat finger-free" looks like in CoreConnect.

The three rules

01
Minimum target: 44×44 px
Every tappable element on mobile must be at least 44px wide and tall. This matches Apple's HIG and WCAG 2.5.5. Material Design recommends 48dp — use 44px as the floor, 48 px when you can afford the space.
02
Spacing: ≥ 8 px between targets
Adjacent tappable elements need at least 8px of dead space between them so an imprecise tap doesn't activate the wrong control. For closely-paired actions (mute + camera), 10–12px is more comfortable.
03
Hit area can extend past the visual
An icon may look like 20×20 px, but its tappable area should be the full 44×44 — use padding on the button (not a fixed icon size). The visual stays small; the hit zone stays large.

Reference: industry minimums

Apple HIG
44 × 44
"Provide ample touch targets for interactive elements. Try to maintain a minimum tappable area of 44pt × 44pt for all controls."
Material Design
48 × 48
"Touch targets should be at least 48 × 48 dp with at least 8 dp of space between targets."
WCAG 2.5.5
44 × 44
"The size of the target for pointer inputs is at least 44 by 44 CSS pixels." (Level AAA accessibility requirement.)

CoreConnect's choice: 44px floor, 48px target where possible. Apple's 44pt and WCAG's 44px align cleanly, and since most CoreConnect users access the app on iOS/Android phones in mixed conditions (in a dealership, walking, holding coffee), treating 44 as a strict floor — not an "aspirational" goal — is the safest bet.

Rules of thumb when building new components

Design at 44, scale visuals inside
Start every interactive element at 44×44 and shrink the visual inside (icon 16–20 px, text 13–14 px). Never start with the visual size and wrap a tight button around it.
Use padding, not fixed dimensions
Prefer padding + a min-height over hard width/height. Padding flexes with content (icon-only vs icon+text) and keeps the tap zone consistent.
Group desktop / mobile in media queries
Use @media (max-width:640px) to bump sizes on phones while keeping the desktop UI compact. Tablets (640–1024) usually borrow the mobile sizing for touch use.
Test with the thumb
Hold the phone one-handed. Can the thumb reach every important action? The thumb's natural arc covers the bottom 2/3 of the screen — keep destructive actions away from the bottom-center, primary actions within the arc.
Destructive actions need extra space
"Delete," "End Call," "Discard" must have ≥12 px isolation from adjacent buttons. A misplaced tap on End Call is irreversible.
Inputs & selects need 44 too
Form controls (input, select, textarea) are taps too. Set min-height:44px in mobile media queries. font-size:16px prevents iOS Safari's zoom-on-focus.

Where to apply this. Phase 1 of the responsive build added the mobile drawer and toolbar collapse, but didn't yet bump touch targets on the elements that stayed visible. Phase 1.5 (or Phase 2's first task) should be a "touch-target pass" — sweeping the existing mobile media query and raising each ✕ FAIL item in the audit above. Once that's done, every CoreConnect surface will be truly fat-finger-free on phones and tablets.
